# client UI 표준안 적용 계획

작성일: 2026-09-28  
상태: 구현 완료, 브라우저 육안 검수 대기  
대상: `biobigdata-qc-client`  
기준 문서: 저장소 상위의 `Design_ComponentGuide.pdf` (Ver 1.0.0)

## 1. 목표와 적용 범위

품질관리 업무 화면에 PDF의 관리자·시스템 관리자 포털 스타일을 적용한다. 우선 색상·글꼴·헤더·사이드바·버튼을 통일하고, `/dashboard`에서 검수한 뒤 공통 변경이 다른 화면에 미치는 영향을 확인한다.

- 1차: 공통 디자인 변수, 폰트, 기존 헤더·사이드바의 시각 스타일, 공통 버튼, 대표 화면의 제목·여백.
- 2차: 사이드바 펼침/접힘 동작과 접힌 상태의 탐색.
- 후속: 표·입력·탭·모달·차트 등 개별 컴포넌트의 상세 표준화.
- `biobigdata-qc-gw-client`, 서버, API 계약, 품질검증 업무 로직은 수정 범위에 포함하지 않는다.
- PDF의 메뉴명·사용자 정보는 디자인 예시로 취급한다. 실제 메뉴 구조와 연결된 사용자 데이터를 사용한다.
- PDF에 보이는 즐겨찾기·전체메뉴·세션 타이머 등은 별도 기능이므로 이번 시각 적용만을 위해 추가하지 않는다.
- 배너는 현재 적용할 실제 영역을 먼저 식별한다. PDF 문서의 제목 장식을 서비스 배너로 복제하거나 신규 홍보 영역을 임의로 만들지 않는다.

## 4. 실행 순서

### 단계 0 — 비교 기준과 자산 준비

- [ ] 변경 전 `/dashboard` 화면과 주요 버튼·메뉴·모달 상태를 캡처한다.
- [x] PDF p.2, 7, 10, 13, 31, 32를 기준으로 색상·치수 매핑을 정리한다.
- [x] Pretendard GOV 파일과 라이선스를 확보한다. 일반 Pretendard와 구분한다.
- [x] 공식 로고 자산이 있으면 사용한다. 없으면 기존 서비스명과 아이콘을 유지하며 배치부터 맞춘다.
- [x] `h-9`, `text-xs`, `bg-primary/10` 등 공통 규격을 덮어쓰는 사용처를 파악한다.

완료 조건: 구현에 사용할 규격, 준비된 자산, 임시로 적용할 디자인 값이 구분되어 있다.

### 단계 1 — 색상과 타이포그래피

- [x] `app/globals.css`에 PDF의 주요 파랑·회색·상태 색상을 정의한다.
- [x] 기존 `--primary`, `--foreground`, `--muted-foreground`, `--border` 등에 역할별로 매핑한다.
- [x] `--primary-pressed` 등 필요한 상태 변수와 헤더·사이드바 전용 변수를 추가한다.
- [x] PDF의 빨간 Accent와 현재 UI의 일반 hover용 `--accent`를 구분한다. 일반 메뉴 hover에 빨간색이 확산되지 않게 한다.
- [x] 주요 액션과 성공·위험·품질등급 색상을 구분한다. 기존 초록색을 일괄 파란색으로 치환하지 않는다.
- [x] 로컬 폰트를 `next/font/local`로 연결하고 `--font-sans`에 적용한다.
- [x] 본문·제목·설명용 크기와 줄 높이를 정의한다. 개별 `text-*`, `leading-*` 사용처도 확인한다.
- [x] 코드·식별자·수치 등에 쓰이는 `font-mono`는 별도 용도로 관리한다.
- [x] 1차는 현재 기본 밝은 화면 기준으로 검수한다. `.dark` 변수의 존재를 확인하되 별도 다크 테마 재설계를 추가하지 않는다.

완료 조건: 실제 렌더링 글꼴이 Pretendard GOV이며, 주요 액션과 본문에 표준 색상·타이포그래피가 적용된다.

### 단계 2 — 헤더와 사이드바의 시각 적용

- [x] 헤더 높이를 64px로 맞추고 남색 배경에서 서비스명·사용자명·아이콘·버튼 대비를 확보한다.
- [x] 기존 계정 모달과 로그아웃 동작을 유지한다.
- [x] 사이드바 너비를 260px로 변경하고 전용 배경·글자·hover·선택 변수를 연결한다.
- [x] 메뉴 그룹 제목과 탐색 항목의 계층을 현재 정보 구조에 맞춰 매핑한다.
- [x] 하위 메뉴의 글자를 13px/20px 기준으로 조정하고 선택 상태와 펼침 상태를 구분한다.
- [x] 메뉴 이동에는 링크, 그룹 열기에는 버튼 등 의미에 맞는 요소를 사용하고 `aria-current`, `aria-expanded`를 연결한다.
- [x] 상세 경로에서도 올바른 상위 메뉴가 활성화되도록 경로 판별을 확인한다.
- [x] `DashboardShell`의 본문에 필요한 `min-w-0`, `min-h-0`와 overflow 설정을 검토한다.
- [x] 메뉴 자체의 스크롤과 본문 스크롤을 확인하고 품질 점수 기준 트리거의 가독성을 맞춘다.

완료 조건: `/dashboard`에서 헤더·사이드바 규격이 맞으며, 긴 메뉴명과 긴 사용자명 때문에 본문이 밀리거나 버튼이 겹치지 않는다.

### 단계 3 — 공통 버튼과 대표 화면

- [x] 기본 버튼을 40px/6px, 작은 버튼을 32px/4px로 맞춘다.
- [x] 필요한 경우 28px 버튼을 명시적 크기로 추가하고, 대형 버튼은 48px로 매핑한다.
- [x] Filled·Outlined·보조 버튼의 기존 variant 사용처를 확인한 뒤 역할별 스타일을 연결한다.
- [x] `active`에 PDF Pressed 색상을 적용하고 `disabled`는 지정 색상을 사용한다.
- [x] hover와 키보드 focus는 별도로 정의한다. PDF가 지정하지 않은 상태는 프로젝트 적용 규칙으로 기록한다.
- [x] 사용자 정의 `className`이 표준 높이·글자 크기를 덮어쓰는 곳은 해당 용도에 맞는 크기로 정리한다.
- [x] `/dashboard`의 제목을 24px/34px 기준으로 맞추고 버튼과 입력 필드의 높이 차이·정렬을 확인한다.
- [ ] 로그인 화면의 주요 버튼과 계정 모달 등 공통 변경 영향을 받는 곳도 함께 검수한다.

완료 조건: 대표 화면에서 기본·눌림·비활성·키보드 focus 상태가 구분되고 버튼 크기 변경으로 폼이나 모달이 깨지지 않는다.

### 단계 4 — 1차 통합 검수

- [ ] 1920×960에서 PDF 규격과 변경 전후 화면을 비교한다.
- [ ] 추가 검수 크기인 1440×900, 1280×800에서 메뉴·본문·모달의 잘림과 가로 스크롤을 확인한다.
- [ ] `/dashboard`, `/dashboard/quality-results`, `/dashboard/data`, `/dashboard/indicators`, 지표 상세, `/dashboard/agent`를 확인한다.
- [ ] `/`, `/signup`에서도 폰트·버튼·오류 문구의 표시를 확인한다.
- [ ] 메뉴 이동, 그룹 펼침, 계정 모달, 로그아웃, 키보드 탐색을 확인한다.
- [ ] 검수 과정의 품질검증 실행 등 데이터 변경 동작은 테스트 환경과 테스트 데이터로 확인한다.
- [ ] 버튼 normal·hover·pressed·disabled·focus, 빈 상태·로딩·오류 상태를 확인한다.
- [ ] 아래 정적 검사와 빌드를 실행한다. 기존 오류와 이번 변경으로 발생한 오류를 구분해 기록한다.

```sh
pnpm exec tsc --noEmit
pnpm lint
pnpm build
```

명령은 `biobigdata-qc-client`에서 실행한다. 스타일 변경 자체를 반복 검증하는 단위 테스트는 추가하지 않고 브라우저 확인과 정적 검사에 집중한다. 실행할 수 없는 검수 항목은 이유와 미확인 범위를 기록한다.

완료 조건: 1차 대상의 시각 검수와 기능 회귀 확인이 끝나고, 검사 결과·변경 전후 화면·남은 항목이 정리되어 있다.

### 단계 5 — 2차 사이드바 접힘 기능

- [x] 사이드바를 260px와 64px 사이에서 전환하는 토글을 제공한다.
- [x] 상태는 셸에서 관리하고 사이드바에 전달한다. 새 전역 상태 라이브러리는 도입하지 않는다.
- [x] 접힌 상태에서 아이콘의 접근 가능한 이름과 툴팁을 제공한다.
- [x] 하위 메뉴는 키보드와 클릭으로 열 수 있는 팝오버 등으로 제공한다.
- [x] 현재 메뉴 표시, 펼침/접힘 후 focus, 본문 너비 재계산을 확인한다.
- [x] 상태 전환과 하위 경로 선택 판별에 대한 필요한 동작 테스트를 기존 테스트 환경 유무에 맞춰 결정한다.

완료 조건: 접힌 상태에서도 모든 메뉴에 접근 가능하며, 화면 공간 확보와 키보드 탐색이 함께 동작한다.

## 5. 권장 변경 단위

1. 색상 변수·폰트·타이포그래피.
2. 헤더·사이드바 스타일·본문 레이아웃.
3. 버튼·대표 화면 조정·다른 화면 영향 수정.
4. 검수 결과 정리.
5. 사이드바 접힘 동작.

각 단위에서 실제 화면을 확인하며 다음 단계로 진행한다. 새 승인 절차를 추가하는 의미는 아니다. 개별 컴포넌트의 상세 표준화는 1차 결과에서 발견한 차이를 목록화해 후속 작업으로 이어간다.

## 6. 1차 완료의 의미

1차 완료는 공통 색상·글꼴·외곽 레이아웃·버튼의 우선 적용을 뜻한다. PDF 전체 컴포넌트 준수 완료를 의미하지 않는다. 최종 보고에는 적용한 규격, 임시 디자인 값, 검수 결과, 후속으로 남은 컴포넌트를 함께 기재한다.

## 7. 구현 결과 및 추정값 기록

구현일: 2026-09-28

### 7.1 원본 확인과 적용 결과

- `Design_ComponentGuide.pdf`의 p.2, 7, 10, 13, 31, 32를 PNG와 SVG로 직접 렌더링해 표기값과 시각 예시를 대조했다.
- PDF p.2의 Primary/Secondary/Gray/System 팔레트, p.10의 Pretendard GOV 타이포그래피, p.13의 버튼 크기·radius·상태값을 공통 토큰과 버튼에 적용했다.
- PDF p.31의 관리자 GNB 높이 64px과 벡터 배경값 `#003C73`, p.32의 LNB 펼침 260px·접힘 64px과 벡터 배경값 `#0C2943`을 적용했다. 배경 HEX는 본문 표에 명시된 값은 아니지만 PDF 벡터 원본에서 직접 확인한 값이다.
- Pretendard GOV v1.3.9의 공식 `PretendardGOVVariable.woff2`와 SIL OFL 1.1을 `app/fonts/`에 포함하고 `next/font/local`로 연결했다. 일반 Pretendard나 외부 CDN은 사용하지 않는다.
- 사이드바 탐색 항목은 `Link`, 결과 그룹과 접힘 토글은 `button`으로 구분했다. 상세 경로를 포함한 `aria-current`, `aria-expanded`, 접힌 상태의 툴팁과 키보드로 여는 결과 하위 메뉴를 추가했다.
- 공통 버튼은 기본 40px, small 32px, extra small 28px, large 48px로 매핑했다. 로그인·회원가입 CTA에는 large를, 테이블 페이저와 제한된 보조 액션에는 extra small을 적용했다.
- `/dashboard`와 결과·통계·지표DB 대표 화면의 제목을 24px/34px, 설명을 13px/20px로 맞추고 업무 영역 여백을 조정했다.

### 7.2 PDF에 명시되지 않아 추정한 값

아래 값은 PDF의 명시 규격으로 간주하지 않는다. 팔레트와 p.31~32 예시를 바탕으로 이 프로젝트에 임시 매핑한 값이다.

| 항목 | 적용값 | 추정 근거 |
| --- | --- | --- |
| 주요 버튼 hover | Primary Blue 50 `#0081F9` | PDF는 Normal·Pressed·Disabled만 명시하므로 인접 팔레트 단계를 사용 |
| 키보드 focus | Primary Blue 60의 40% 3px ring | 기존 포커스 가시성을 유지하면서 주요색에 맞춘 프로젝트 규칙 |
| 사이드바 메뉴 hover | Secondary Blue 80 `#003C73` | 어두운 LNB 배경과 p.2 Secondary 팔레트의 인접 단계 |
| 사이드바 선택 배경 | Primary Blue 60 `#0A6BE9` | 선택 배경 HEX가 명시되지 않아 주요 액션색을 임시 사용 |
| 헤더 아이콘 영역 | 흰색 10% 배경 | 기존 아이콘을 유지하면서 남색 배경에서 대비를 확보하기 위한 값 |
| 업무 영역 좌우 여백 | 기본 24px, large 화면 32px | p.7의 허용 margin 값 중 현재 콘텐츠 밀도에 맞춰 선택 |
| 사이드바 전환 시간 | 200ms | PDF에 모션 규격이 없어 짧은 레이아웃 전환값을 사용 |
| 툴팁 표시 지연 | 250ms | 접힌 메뉴의 탐색성과 우발 노출 사이를 조정한 동작값 |

공식 로고 파일은 저장소에서 확인되지 않아 기존 `Database` 아이콘과 서비스명을 유지했다. PDF의 로고를 복제하지 않았다.

### 7.3 단계별 검증 기록

| 단계 | 검증 | 결과 |
| --- | --- | --- |
| 0 기준·자산 | PDF 6개 페이지 직접 렌더링, 공식 폰트/라이선스 확인 | 통과 |
| 1 색상·폰트 | `pnpm exec tsc --noEmit`, diff whitespace 검사 | 통과 |
| 2 헤더·LNB | `pnpm exec tsc --noEmit`, 의미 요소와 ARIA 정적 확인 | 통과 |
| 3 버튼·대표 화면 | `pnpm exec tsc --noEmit`, 크기·상태 클래스 검색 | 통과 |

| 4 lint | `pnpm lint` | 기존 오류 4건과 경고 2건으로 실패. 이번 변경 파일에서는 신규 lint 오류 없음 |
| 5 접힘 기능 | 타입 검사와 프로덕션 빌드 | 통과 |

브라우저 자동 캡처용 Chromium의 임시 설치가 허용되지 않아 1920×960, 1440×900, 1280×800 육안 검수와 변경 전후 캡처는 수행하지 못했다. 따라서 실제 폰트 렌더링, 긴 사용자명, 메뉴 flyout의 화면 경계, 모달·hover·pressed·focus의 픽셀 단위 비교는 후속 브라우저 검수 범위로 남는다. 로그인·계정·로그아웃 및 품질검증 실행처럼 서버나 데이터 변경이 필요한 동작도 실제 브라우저에서는 실행하지 않았다.
